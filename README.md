# 행운번호 연구소 V3.3 — 당첨 데이터 자동 갱신

이 버전은 V3.2 모바일 UI와 번호 생성 기능을 유지하고, **동행복권 당첨 회차 자동 동기화**를 추가합니다.

## 실행

```bash
npm install
npm run dev -- --host 0.0.0.0
npm test
npm run build
```

## 자동 갱신 활성화 (중요)

1. **프로젝트 전체**를 GitHub 저장소에 올립니다. `.github/workflows/update-lotto.yml` 파일을 함께 커밋해야 합니다.
2. GitHub 저장소 → Actions에서 `Update lotto history` → `Run workflow`를 **처음 1회 수동 실행**합니다.
3. 실행 후 변경된 `public/data/history.json`, `stats.json`, `latest.json`이 저장소에 커밋됐는지 확인합니다.
4. 이후 매주 토요일 22:15, 일요일 09:15·15:15(KST)에 예약 확인합니다. GitHub Actions 스케줄은 혼잡 시 지연 또는 누락될 수 있습니다.
5. Vercel 등 GitHub 연동된 호스팅은 데이터 커밋 후 자동 재배포하도록 설정합니다. 자동 갱신은 **배포가 연결되어야** 방문자에게 반영됩니다.

## 데이터 정확성 정책

- 단일 원본: 동행복권의 `selectPstLt645InfoNew.do` 엔드포인트(공식 **공개 API 아님**, 내부 조회 엔드포인트).
- 1회부터 최신 회차까지 **전 회차의 날짜·6개 번호·보너스·1등 당첨금·1등 당첨자 수**를 조회합니다.
- 회차 누락/중복, 번호 오류, 필드 오류, 날짜 오류, 과거 회차로의 역행을 검증합니다.
- 모두 통과한 경우에만 데이터 파일을 갱신합니다. 수집 실패 시 GitHub Action이 실패하므로 마지막 정상 데이터가 남습니다.
- 숫자 출현 횟수는 전체 회차의 **6개 본번호에서만 재계산**하며 HOT/COLD, 번호별 통계에 반영합니다.
- QR 판정은 **앱이 확인 가능한 회차만** 수행하고 공식 확인 링크를 제공합니다. 구매 영수증을 통한 공식 대조가 최종 기준입니다.

## 초기 동봉 데이터의 한계

현재 ZIP에는 **최신 1245회 표시**와 **1~1245회 누적 출현통계**가 들어 있으나, QR 상세 비교용 `history.json`은 1226~1245회 부분 기록만 들어 있습니다(1226~1241회 보너스 미보유). **GitHub Actions 최초 수동 실행 성공 후** 1회~최신 회차의 완전한 상세 기록이 생성됩니다. 초기 ZIP 상태에서 과거 QR 전체 판정이 가능하다고 해석하지 마세요.

## 수동 동기화

```bash
npm run sync:data
```

인터넷 연결이 필요하고 조회 서버가 접속을 허용해야 합니다. 추첨 직후 발표가 늦어질 수 있어 토요일·일요일 여러 번 조회합니다. 내부 API의 응답 스키마가 바뀌면 `scripts/draw-data.mjs`를 수정해야 합니다.

## 유의

통계 기반 번호 선택은 당첨 확률을 높이지 않습니다. HTTPS 환경에서만 카메라 접근이 가능합니다. GitHub Actions의 쓰기 권한이 제한된 저장소에서는 `Settings > Actions > General > Workflow permissions`에서 권한을 확인하세요.
